# ハイライトルール

`totonoeLog.highlightRules` 設定の完全な形と、ルール同士が競合したときの
解決順。ハイライトが何のための機能かは
[ハイライトルール](../../README.ja.md#ハイライトルール)（README）を参照して
ください。

設定はただの配列なので手で書くこともできます。`.vscode/settings.json` に
コミットすれば、プロジェクトのパターンをチームで共有できます:

```json
"totonoeLog.highlightRules": [
  { "name": "OOM", "pattern": "OutOfMemory", "color": "red" },
  { "name": "timeout", "pattern": "timed? ?out", "color": "orange" }
]
```

`pattern` は大文字小文字を区別しない正規表現で、1行の中の一致箇所は最初の
1つだけでなくすべてに色が付きます。`color` は `red` / `orange` / `yellow` /
`green` / `blue` / `purple` のいずれかです。任意の色コードではなく決まった
名前から選ぶ形にしているのは、明るいテーマ・暗いテーマそれぞれで読める値を
拡張機能側が用意するためです（省略時は `yellow`）。`name` は自分のルールを
見分けるためと、警告文言でルールを名指しするためだけのもので、省略時は
`highlight-<連番>` になります。

2つのルールの範囲が重なった場合は、先に書いたルールが優先されます
（絞り込みたい範囲が狭いルールほど上に置いてください。Interactive View の
▲▼ はそのための操作です）。正規表現として不正なルールや、知らない色を
指定したルールは、そのルールだけが名指しの警告付きで飛ばされ、残りのルール
はそのまま効きます。飛ばされたルールもパネルには表示されるので、その場で
直せます。設定を手で編集すると、開いているパネルの色がすぐ更新されます。
パネルからの書き戻し先は、ルールが既に定義されている場所（ワークスペース
設定にあればそこ、無ければユーザー設定）です。
